# Security context for agents

Before security-related changes, read [SECURITY.md](SECURITY.md) and [WakeboardUK #189](https://github.com/JeremyNevill/WakeboardUK/issues/189). The issue owns current tasks, acceptance criteria, PR links and deployment sign-off; dated reports provide evidence, not duplicate live status.

Archived audits and superseded pointer documents are historical. Use the 9 September reconciliation linked from the security index to interpret old findings. Do not reintroduce their stale severity claims or implement their old checklists independently.

Keep security tests isolated from customer records and live payment, messaging and publishing integrations. Documentation changes do not establish that remediation tests or production verification have passed. Never include real credentials or personal data in reports or commits.
